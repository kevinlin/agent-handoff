# Wrap-up memory

Run this at the end of every non-trivial run, so the next split decision starts smarter. Skip it when the run taught nothing new: a few accurate notes beat many.

Save durable routing lessons as Claude Code auto-memory notes, by its built-in rules: one fact per note, update an existing note instead of adding a duplicate, and delete a note that turned out wrong. Say which repo and what kind of task each lesson came from. Worth recording:

- what was delegated and what the driver kept, and why;
- for each delegated task type, how it went: accepted on the first pass, the number of rework rounds, escalated (with the arbiter's verdict), or taken back after an anomaly;
- the effort each identity ran at, and whether it fit;
- any monitoring anomaly, and what fixed it.

Each job's `result` ends with the worker's lessons-learned lines. Read them for candidates.

A fact every future session must see unconditionally (architecture, commands, conventions) belongs in the repo's `CLAUDE.md` or `AGENTS.md`, not in memory. Memory holds experience, and the instruction files hold rules.
