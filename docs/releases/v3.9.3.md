# v3.9.3: The setup wizard says when a CLI is missing or out of date

Until this release, the wizard that `/agent-handoff config` opens told you whether Codex was found and whether the Copilot and Cursor model lists could be read. It never said a CLI was out of date, and it gave no command to install one. Now it does both for Codex, GitHub Copilot and Cursor. The Claude Code tile is unchanged.

## What the page tells you

Each of the three tiles now carries a status. MISSING means the CLI was not found. UPDATE means it is older than the newest published release.

To find each CLI, the page runs its `--version` and nothing else. Codex is found as before: `HANDOFF_CODEX_BIN`, then the ChatGPT or Codex app bundle on macOS, then PATH. GitHub Copilot must report `GitHub Copilot CLI`, because AWS Copilot CLI uses the same binary name, and `HANDOFF_COPILOT_BIN` is checked first. Cursor is `cursor-agent`, with `HANDOFF_CURSOR_BIN` first. A `--version` call starts no session and costs no premium request. v3.9.1 said opening the wizard runs no new command. That is no longer true.

The newest release of Codex and Copilot comes from the npm registry, as the `latest` tag of `@openai/codex` and `@github/copilot`. Cursor has no registry entry. Its install script, `https://cursor.com/install`, names the current build in a `downloads.cursor.com/lab/<build>/` URL, and the page reads that. If the script names more than one build, or none, Cursor's latest is unknown. The requests send no credentials, time out after 3 seconds, and run while the local probes run.

Versions compare by their leading dotted number, padded with zeros, so `codex-cli 0.147.0` is older than `0.162.1`. A prerelease counts as its stable number. Two Cursor builds with the same date and different hashes count as equal. When either side can't be read, the status is unknown and the tile makes no claim. It still shows FOUND or LISTED then, so neither word means up to date.

Codex shows MISSING, UPDATE or FOUND. Copilot and Cursor show MISSING first, then NO MODELS when the model list failed, then UPDATE, else LISTED.

A missing or outdated CLI gets a `How to install` or `How to update` button, even under NO MODELS. The button opens a native HTML popover, which Esc or Close dismisses. Inside are the command, the detected binary path for an outdated CLI, a note when a `HANDOFF_*_BIN` override is set, a reminder to start the wizard again, and an `Official install guide` link that opens in a new tab.

| CLI | Install | Update | Official page |
| --- | --- | --- | --- |
| Codex | `npm install -g @openai/codex` | `codex update` | https://developers.openai.com/codex/cli |
| GitHub Copilot | `npm install -g @github/copilot` | `copilot update` | https://docs.github.com/en/copilot/how-tos/set-up/install-copilot-cli |
| Cursor | `curl https://cursor.com/install -fsS \| bash` | `cursor-agent update` | https://cursor.com/docs/cli/installation |

The wizard also starts when a CLI prints nothing for `--version`. Before, that stopped it from starting.

## Known gaps

- The install line is one fixed command per CLI. Other installers, such as Homebrew, are on each official page.
- A typed `copilot update` runs the first `copilot` on PATH. When AWS Copilot CLI sits earlier on PATH, that is a different binary from the one the wizard found, which is why the popover shows the detected path.
- A Codex bundled in the ChatGPT or Codex app updates with the app.
- Cursor's install script is not a stable API. If its format changes, Cursor's latest reads unknown.
- A Copilot whose `--version` times out is reported missing.
