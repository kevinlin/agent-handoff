# v3.7.1: per-identity permission posture

Every identity carries `permission_mode`: `default` or `allow-all`. Existing
configs resolve missing values to default after the per-field merge. Both
setup UIs expose the choice; presets remain default. Changing posture does not
clear model/effort smoke verification.

Default now runs Claude with dontAsk and Read Glob Grep Edit Write Bash.
Codex inherits the user's config with no sandbox flag, preserving the worker
commit contract. Copilot keeps allow-all-tools and path/URL verification.
Only Claude default changes behaviour. Allow-all selects the provider's native
unrestricted mode, not one shared security posture.

Read-only wins over the retained Claude env override and configured posture.
Resume inherits read-only and posture; absent parent posture means default.
Job meta distinguishes requested posture/source from effective permission mode,
and warnings follow the effective mode. Receipt schema remains v6.

## Deliberate deviations and limitations

See [the configuration schema](../specs/design_agent-identities-and-config.md#permission-posture-v371)
for the full flag table and named deviations from the research doc: inherited
Codex config instead of workspace-write, no exec ask-for-approval flag, and
Copilot allow-all-tools instead of repo-specific command rules.

- **No OS-level sandbox for claude default.** This changes permission rules only,
  not enforced workspace-only IO or network denial.
- **Codex denials are not counted.** Implementing sandbox-refusal detection is
  out of scope.
- **permission_denied is advisory, not enforced.** DONE follows the exit code,
  and status warns but still succeeds. Verify edits and check markers on disk.

The regression suite covers config merging, both setup paths, backend argv,
read-only precedence, resume inheritance, legacy metadata and effective-mode
warnings. Live provider execution is a separate behavioural probe; generated
flags alone do not prove containment or that checks ran.
