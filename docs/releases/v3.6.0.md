# Agent Handoff 3.6.0

3.6.0 adds one command. `/agent-handoff transcript` renders a delegated job's `log.jsonl` as a readable HTML conversation and opens it.

The gap it closes: a delegated job leaves a full event log, and nothing in the skill read it back. Phase 3 tails the last few lines for liveness, `delegate-codex.sh result` prints the final message, and the receipt counts jobs. To see what the worker actually ran, you read raw JSONL.

## What Changed

- `/agent-handoff transcript [<pid|jobId|folder>]` resolves a selector to a job directory, renders it, and opens the page. Omitted or `last` means the newest job by `submitted_at`; a folder path, an exact jobId, a pid, and a remembered label also resolve.
- Ambiguity is reported, never guessed. A label matching both a job and its `-r2` resume round prints both names and exits non-zero. A digit that is both a pid and part of a label is the same collision and gets the same treatment.
- `assets/transcript-viewer.html` is the entire viewer — vendored marked v15.0.12, normalizer, escaping boundary, and renderer in one file. It opens from `file://` with no network access.
- Both log formats are read by the same normalizer: Codex `item.started`/`item.completed` envelopes and Claude `stream-json` assistant/user events. Each started/completed pair and each `tool_use`/`tool_result` pair folds into one row at the first event's position.
- A failed edit renders as an error, not as a completed file change. An unrecognized event or content block keeps a row carrying its source object rather than disappearing.
- A malformed interior line becomes a visible `unparsed` row. A truncated final line — a live job mid-write — is reported as a partial log instead of a broken row.
- Dropping a `log.jsonl` onto the page renders it, with an empty job record rather than a merge into whatever job the page was generated for. All parsing lives in the page's JavaScript so the drop path needs no second parser.
- `scripts/render-transcript.py` writes to `<repo>/.handoff/transcripts/<jobId>.html` and warns if that path is not ignored by Git. A transcript embeds captured command output.

## Untrusted Input

Log content is untrusted. Every string reaches the DOM through `textContent`, with one exception: agent and reasoning text goes through marked, which passes raw HTML through by design. Three renderer overrides close that — emitted HTML is escaped, and link and image schemes outside `https`, `http`, `mailto`, and `#` are rendered as text rather than as attributes.

`tests/test_transcript_viewer.mjs` asserts emitted markup against a tag and attribute allowlist rather than scanning for strings like `onerror`, which an escaped payload would trip falsely. The tests extract the shipped page's own script blocks and run them in node, so there is no second copy to drift.

## Release Gate

- `python3 -m unittest discover -s tests`
- `node --test tests/test_transcript_viewer.mjs`
- `bash scripts/check-skill-repo.sh .`
- `python3 scripts/run-test-prompts.py`
- `bash install.sh --dry-run`
- Every job under a real repo's `.handoff/jobs/` renders without error, with row counts matching the prototype run and no job reporting a partial log.
- `grep -c innerHTML assets/transcript-viewer.html` returns 1, in `renderRow`, applied only to `renderMarkdown` output.

Tagging or publishing this release remains a separate hard stop.
