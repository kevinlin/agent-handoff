# v3.9.0: Cursor CLI as the fourth backend

A `cursor` identity runs `cursor-agent -p --output-format stream-json` as a Handoff job. It gets the same job directory, monitor loop, bounded fix rounds, worktree handling, and receipt evidence as Codex, Claude, and Copilot. Handoff resolves `HANDOFF_CURSOR_BIN` first, then `cursor-agent` on PATH. The `cursor` command is the IDE launcher.

A Cursor model is a catalogue slug that includes its effort. Its Handoff effort value is always `model`; `auto` is refused. The web wizard reads `cursor-agent models` when it opens and shows available slugs. A configured slug no longer in the catalogue stays visible, but smoke refuses it before a paid read-only request. The terminal wizard accepts a typed slug. A model rejected at launch leaves a FAILED Handoff job with Cursor's message in `stderr.log` and no events in `log.jsonl`.

## Receipt change

Receipt schema v7 adds `cursor_jobs` and `cursor_job_durations`. Older receipts fail validation. Regenerate them with `make-receipt.py`, passing `--cursor-jobs` alongside the other backend counts. The generator measures durations from the job directories. The cost receipt shows Cursor token counters and the model from the job's `init` event when present. Cursor reports no cost figure, so its cost cell says `n/a - no cost figure`.

## Cursor limits

- `default` and `allow-all` both use Cursor's force mode. The posture setting does not narrow a Cursor writing job. Only the user's or project's deny rules in `.cursor/cli.json` narrow it. Handoff does not write that file and prints a bypass warning for each writing job. Read-only uses `--mode plan`.
- Cursor's attribution setting can add a `Co-authored-by: Cursor <cursoragent@cursor.com>` trailer to worker commits, including e2e commits. Handoff reports the trailer and leaves it in place.
- `(NO ZDR)` in a model's display name means no zero data retention. A delegated job sends repository contents to that model.
- Resuming a session Cursor never persisted does not fail. Cursor starts a new, empty session under the same id, so a fix round against it runs without the parent's context and nothing lands in `stderr.log`. The flow tells the driver to resubmit with the full packet when a round shows no memory of its parent.
- A shell call can fail with `spawn /bin/zsh ENOENT` when the model mistypes a long workspace path as its working directory. The shell is present; the path is not. The live verification run hit this on `gpt-5.4-mini-low` and recovered in one fix round that named the typo.

## Known gaps

- The chip diagrams in `docs/user-guide/diagrams/delegate-paths.svg`, `identities.svg`, and `handoff-lifecycle.svg` still draw three backends. The receipt card in `evidence-flow.svg` also keeps its three-name label because a fourth name does not fit at the same font size.
- The shape of a mid-run Cursor API failure has not been observed. The monitor reads both `log.jsonl` and `stderr.log`.
- Running without `--trust` has not been probed; Handoff always passes it.
- The message from a logged-out `cursor-agent -p` run has not been recorded. The logged-out `cursor-agent models` error is handled in setup.
