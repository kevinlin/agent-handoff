# Agent Handoff 3.7.0

3.7.0 adds a third execution backend. `backend = "copilot"` runs a delegated job on GitHub Copilot CLI, with the same jobId, job state, monitoring loop, bounded fix round, worktree lifecycle, and receipt evidence the codex and claude backends already had.

The gap it closes is narrower than "another vendor". v3.5.0 cut a seam for a second backend and claimed it was an abstraction. A third one is the test of that claim: if copilot needed a parallel implementation, the seam was two special cases wearing one name. It did not. The job lifecycle is unchanged, and `delegate-codex.sh` branches in four places — binary discovery, the exec line, the effort enum, and the event parser.

## What Changed

- `backend = "copilot"` is a first-class value in the config, the delegation primitive, the setup engine, the wizard, the receipt, the cost receipt, and the transcript viewer.
- The binary is identified by its `--version` output rather than by its name. AWS Copilot CLI is also called `copilot`, and PATH order decides which one is found first. Submit, resume, the setup availability check, and the wizard share one resolution contract, so setup cannot refuse an install the worker would have used. `HANDOFF_COPILOT_BIN` overrides and is identity-checked too.
- The session id is assigned at submit. Copilot emits `sessionId` only in its terminal event, so a job that died mid-run would have left nothing to resume. Handoff generates the uuid, writes it to `$JOB/session_id` before launch, and records `session_id_source=assigned` in `meta`. A job killed before its terminal event resumes with its context intact.
- `--read-only` becomes `--mode plan`, which never carries `--allow-all-tools`.
- Receipt schema v6: `copilot_jobs` and `copilot_job_durations` join the two existing pairs, and `roles_used[].host` accepts `copilot`. A v5 receipt now fails validation, which is the signal to regenerate it.
- The cost receipt reports Copilot's meter as premium requests and nano-AIU, labelled AI credits. No currency figure is emitted, because Copilot reports none.
- The transcript viewer parses copilot logs, gated on the payload's backend.
- The setup wizard renders Copilot's model as a text field and validates the model-and-effort pair against the real CLI on apply and smoke.

## What The Probes Settled

The design rests on eleven live `-p` runs against GitHub Copilot CLI 1.0.83, recorded with their evidence in `docs/research/github-copilot-cli-specification.md`. Four results changed the implementation:

- **`--mode plan` plus `--allow-all-tools` is a silent-failure combination.** Plan mode still won on disk, but the agent emitted zero denial events, exited 0, and claimed a file write and a shell mutation that never happened. Nothing in the event stream marked it. The two flags are now mutually exclusive in the generated `run.sh`, asserted by a test.
- **A repository check really runs under `--allow-all-tools`.** `bash scripts/check-skill-repo.sh .` executed in a fresh clone with its own `SUMMARY fail=0 warn=1` captured inside `tool.execution_complete`, zero denials, exit 0. That is the capability, not the worker's closing statement about it.
- **Credit counters are cumulative; token counters are not.** A resumed session's `tokenDetails` are per invocation and sum across a parent and its fix round, while `totalPremiumRequestCost` and `totalNanoAiu` are running session totals. Adding the top-level figures would have double-counted every fix round.
- **Effort-for-model validation is free in one direction.** An unsupported pair is refused before any session exists, with a plain-text stderr line and no premium request spent. A valid pair starts a real session and costs one. The wizard says which case is which and never claims validation is free outright.

## What Is Not There

- No model catalog, probed or cached. Copilot exposes none: `copilot model` is not a command, and `availableModels` inside a run's JSONL is `auto`'s routing candidate set — it moved on the probing account inside a day while the configured model kept working. The wizard takes a typed model and validates the pair.
- No `model = "auto"` for a configured identity. The refusal is conceptual, not mechanical: `auto` resolves per request, so it would make the receipt record what the vendor picked rather than what the repo configured.
- No `HANDOFF_COPILOT_PERMISSION_MODE`. Naming an escape hatch is not mitigation when nothing tells the user to reach for it. The posture is the default, the submit-time warning, and typed-denial detection in `status` and `result`.
- No Copilot entry in the setup presets, no rename of `delegate-codex.sh`, no config `schema_version` bump, and no credential stripping in the copilot branch — Copilot authenticates through `gh auth` and reads none of the `ANTHROPIC_*` or `CLAUDE_CODE_*` variables that stripping exists for.

The live end-to-end pass needs a real Copilot CLI and a scratch repo, and is a separate manual step. Tagging or publishing this release remains a separate hard stop.
