# Agent Handoff 3.6.1

3.6.1 adds one command. `/agent-handoff cost-receipt` reads a saved Handoff Session Receipt and the delegated job logs it indexes, and writes what the run consumed as a markdown page and an HTML page.

The gap it closes: a finished run leaves a receipt that counts jobs and times them, and job logs that carry token counters and, on claude-backed jobs, the CLI's own cost figure. Nothing read the two together, so answering "what did that run consume" meant grepping JSONL by hand.

## What Changed

- `/agent-handoff cost-receipt [<receipt-file>]` renders a receipt and opens the page. Omitted or `last` means the newest saved receipt under `.handoff/receipts/`, chosen by the stamp in its filename rather than by mtime, so copying a file does not reorder the set.
- Output goes to `.handoff/cost-receipts/`, named `cost-receipt-<stamp>.{md,html}`. A re-run overwrites in place.
- Every number is read from a file. Codex jobs contribute token counters and no cost figure, because that work runs on a subscription and the Codex CLI emits none. Claude jobs contribute `total_cost_usd` verbatim and unrounded, labelled CLI-reported.
- Two summary figures: what ran on a Codex subscription, and what ran outside the driver session. Codex jobs belong to both populations on purpose. The page says so, and no line adds them. No saving, avoided cost, or context-saved figure is emitted anywhere, and no price table is applied.
- A missing measurement prints `unknown`. A measured zero prints `0`. A summary column with any unmeasured job prints a floor and how many jobs were measured.
- The driver row is scoped to the run's interval, derived from the receipt's stamp and its `duration`, so a session that hosted two runs reports two different rows and a transcript that grows afterwards does not change an already-rendered receipt. Input with no derivable end is labelled unscoped rather than silently totalling the session.
- A job with no `exit_code` is FAILED, not RUNNING: a worker that died without writing one leaves no exit code. `handoff_runtime.job_state()` is now the single implementation, shared with `render-transcript.py`.
- `assets/cost-receipt.html` is self-contained, built on the transcript viewer's tokens, with no network access and no `innerHTML`.

## Untrusted Input

The receipt file is untrusted text. It is parsed fail-closed: exactly one receipt block, no duplicate field keys, `receipt_schema_version` 5 exactly, job ids restricted to safe path segments and re-checked against the resolved jobs directory, per-backend counts agreeing with the entries they claim to count, and each job's recorded backend agreeing with the list it appears under. Any of those refuses the run and writes nothing.

The HTML export is enumerated, not passed through: only job id, label, role, backend, model, state, token counters, cost, denial count, and the repeat flag reach the payload. Denial command strings and prompt text are never exported — a denial contributes a count and nothing else. The payload slot is written by `handoff_runtime.inject`, which escapes `<` so a closing-script sequence in captured text cannot end the element, and every value reaches the DOM through `textContent`.
