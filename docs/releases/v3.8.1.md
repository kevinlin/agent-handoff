# v3.8.1: Copilot models are picked, and the receipt is kept

## Copilot models are picked, not typed

A `copilot` identity's model is chosen from a list in `/agent-handoff config`,
the way Codex and Claude models already are. The list is what the authenticated
account is entitled to, and each entry carries the reasoning efforts that model
accepts, so the effort control offers only what the chosen model takes.

The Copilot CLI publishes no catalogue of its own: it has no model-list
subcommand, and a wrong `--model` is refused without naming the alternatives.
So the entitlement API is read directly, with the bearer `gh auth token`
returns. Entries no coding session can select are dropped — embeddings, legacy
chat models, and anything an org policy has not enabled. Nothing here spawns
`copilot`, so opening the page still costs no premium request.

On copilot the served catalogue is also the list of valid model names: a
request naming anything else is refused before a preview is built, so neither
the page nor its API can write a pair nothing checked. The reader fails closed
on any field it cannot parse, and one malformed entry costs that entry rather
than the wizard, which builds its state during controller construction.

Apply no longer runs each configured pair past the CLI before writing the
config. The catalogue settles model and effort before the config exists, and
claude and codex never had such a check, so the three backends are now alike
here. The same check still runs on the smoke path, which is what sets
`verified`, and `/agent-handoff tryout` still runs a real task per identity.

When the catalogue cannot be read — no `gh`, no network, or a data-residency
tenant serving its catalogue from a per-tenant host — the wizard offers no
Copilot model and names the login to fix. It does not fall back to a typed
name. A Copilot identity already in the config keeps its model and stays
selectable, so reopening the page offline cannot quietly rewrite a working
config — at the effort already configured, since nothing available knows what
else that model accepts.

Two limits are recorded rather than engineered around: the endpoint is not a
documented GitHub API contract, and Handoff does not discover a tenant-hosted
one. The token the read is made with never reaches the served page state or a
log line. `docs/specs/design_agent-identities-and-config.md` holds the design; `docs/specs/design_agent-handoff.md`
carries the guard that went away and what replaced it.

## Wrap up leaves the receipt on disk

A run's Handoff Session Receipt is now written to
`.handoff/receipts/receipt-<stamp>.md` without being asked. It used to take a
`--save` flag that neither `SKILL.md` nor `references/claude-driven.md`
mentioned: Phase 5 said "emit", which puts the block on stdout and nowhere
else. Meanwhile `/agent-handoff cost-receipt` and `/agent-handoff visualise` read
their default input from that directory, `/agent-handoff tryout` closes by
writing one there, and the README already described the receipt as written at
wrap up. Whether a run
left its evidence behind came down to the driver noticing an option the prose
it loads never named.

`--no-save` is the opt-out, for the two cases that want the block alone: the CI
roundtrip that pipes into `validate-receipt.py`, and a past run's receipt
regenerated with `--ended-at` that should not deposit a second file.

If you call `make-receipt.py` from a script of your own, `--save` was removed
rather than deprecated: argparse now exits 2 on it, before any receipt is
generated. Delete the flag from those commands, and use `--no-save` where you
wanted stdout alone.

One more guard came with this. A field value containing a newline used to pass
validation and then serialize into a receipt that `extract_block()` truncates,
losing every field after it. Printing it made that visible; saving it by
default would have left the broken receipt on disk for the cost receipt and the
session page to read. Such a value is now refused before anything is printed or
written.

One claim went the other way. `docs/specs/design_agent-handoff-evidence.md`
said the generator re-read its written receipt with `validate-receipt.py`, and
it never did — validation is a single pass over the fields before anything
reaches disk. Re-reading a file the same process wrote a line earlier checks
the filesystem rather than the receipt, so the claim is dropped from the spec,
the user guide and the evidence diagram instead of being implemented.

Config schema stays at 2 and receipt schema at 6.
